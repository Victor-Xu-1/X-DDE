# 开发与发布

[返回项目介绍](../README.md) · [仓库工程要求](../AGENTS.md) · [科学与服务器验收](server-acceptance.md)

X-DDE 的科学能力来自明确的请求契约、同一任务路由和独立科学环境。新增或替换软件需接入现有注册表、BackendRouter、Store/Worker 和研究资产管理；不要另外实现一套竞争性的工作台、任务队列或数据管理。

基础分子性质由独立 RDKit 环境执行，通过 `chemistry` 注册项和同一 Worker 调度；不要求 OpenDDE 代码、预测模型或 GPU。描述符与 CSV 的计算实现只有一份，使用原生记录的文件身份和记录编号驱动二维、三维预览。执行资源不写入历史请求 JSON，因此已保存任务与固定示例的输入摘要保持有效。

分子状态枚举保留质子化方法给出的候选顺序。每个质子化候选优先保留其输入互变异构形式，再按 RDKit 结构评分选择其他形式；总预算截断使用这一顺序，不能改用 SMILES 字母顺序。该结构评分不是 pH 状态占比或实验优势状态预测；已定义的立体化学、原子对应、原始文件与有限枚举提示仍须保留。

新任务的构象最小化默认预算为 1000 步，由同一 `StateOptions` 生成前端设置。实际 STAT6 案例的 46 个 MMFF94s 构象在该预算内收敛；结果继续记录每个构象的真实收敛标记。历史请求保留已保存的预算。9BIG 结构准备使用已核对的替代坐标 A，并以 mmCIF 保留五字符配体标识；PDB 导出须拒绝超出固定字段的结构标识或坐标。

日常维护按[工程质量与验收规范](quality/README.md)执行：先登记问题和唯一负责人，再做独立审查、精确提交的专项 CI、串行整合及合并后确认。前端交互/动效、科学验证分层和可复制的证据清单均在该目录；现有仓库规则与授权边界保持有效。

## Docker 实例与既有任务

默认使用现有 Docker 实例。隔离运行环境通过统一组件安装器接入，不创建第二套任务队列或全局切换 Docker context。运维人员可在组件安装根目录的私有 `container-runtimes.json` 中为个别组件声明本地 Unix socket 和精确的 Docker daemon ID；该文件不是浏览器任务参数。示例仅描述配置格式，不会自动启动实例或导入镜像：

```json
{"schema":1,"engines":{"deepternary":{"endpoint":"unix:///srv/wsl/tmp/x-dde/docker.sock","daemon_id":"replace-with-verified-docker-daemon-id"}}}
```

安装操作先保存不可变的 `container-runtime.json`，所有构建、探针、清理和恢复都使用该位置并验证 daemon ID。只有原生入口检查与清理通过后，组件的 `installed.json` 条目才发布对应运行位置；配置安装目标不改变其他已安装组件。跨存储导入镜像时，还须独立验证镜像配置、所有 RootFS 层及原生入口，保存源镜像和新镜像的真实身份，不能假设 manifest digest 等于经典存储的 config digest。

任务从已安装组件继承运行位置并独立冻结。创建、子进程 attach、取消、完成后清理均读取任务自己的记录；后续配置变更不会将旧任务转向另一实例。daemon ID 不符或记录损坏时明确失败，不能把另一实例中的“容器不存在”当作清理成功。没有此记录的历史任务和旧安装探针继续使用原实例，不能追溯改绑。组件镜像、数据及回滚来源均须保留。

隔离 Docker 需要单独的存储、socket、exec root、资源预算及明确运行授权。软件支持显式运行位置不代表已迁移现有服务器，也不代表模型或科学任务已通过验收。

短期科研验证使用状态目录内的私有 `native-runtime-lease.json`，无需改动 `installed.json` 或组件安装目标。会话具有唯一 ID、明确的创建/截止时间和最多六小时有效期；每个环境记录原安装条目的完整摘要、原镜像、经核验的临时镜像和显式本地实例。原安装身份变更、记录损坏、实例错误或会话过期都会阻止新任务。安装器不读取任务会话，其他环境也不受影响。

任务启动前同时冻结真实镜像、实例和会话来源；取消、子进程 attach 和结果清理继续使用该任务记录，即使会话随后过期或移除也不会转向另一实例。历史格式仍可读取。会话结束后先核对所拥有的任务和容器都已结束，再移除该会话并停止其独立实例；原组件清单全程保持不变。启用临时计算仍须有相应实际计算授权，不能把镜像导入或库加载验证视为模型推理授权。

三元建模新任务默认采用 2 CPU / 4 GiB / seed31；确认页显示预算，专家设置可选择后端契约支持的 CPU、内存和随机种子。复现已固定示例时保留其原资源选项；输入、搜索次数、原生几何校正和科学验收标准不随预算变更。

## 验证改动

按改动范围运行组件及直接使用者的专项检查。没有明确授权，不运行全仓库测试。前端构建与静态检查可以本地完成；所有者共享机器上的科学推理、GPU 或完整模型验收留给 CI / 目标服务器。

```bash
npm ci --prefix frontend
npm run check --prefix frontend
npm run build --prefix frontend
```

选择受影响的具体 Vitest、pytest 或浏览器检查，不使用没有文件选择的全量测试命令。运行环境、原生结果、浏览器行为与科学结论分别记录；界面截图不能替代模型验收。

能力或 DiffSBDD 参数契约变化后，用 `scripts/generate-capability-catalog.py` 同步前端目录；其 `--check` 模式验证现有目录与后端权威是否一致。

Boltz-2 的每条蛋白可选择经过核验的 A3M，或使用 `sequence`、`key` 两列的配对 CSV。
首行必须与该条蛋白序列完全相同，各行保留相同的比对列数；小写插入、缺口和配对键不被改写。
同序列的链共用同一份比对。每份材料沿用现有资产的不可变摘要、版本和来源任务；
原生 A3M 输出登记为 `alignment` 科学版本，可继续用作预测输入，不另建文件仓库。
对包装为多行的 A3M，仅在原生任务快照内规范换行，原始文件保持不变。
界面默认引导选择比对文件；明确选择“单序列探索性基线”才可省略 MSA，并在提交确认页标明限制。
历史请求中缺省的 MSA 字段保持缺省，不改写已经固定的请求或结果摘要。
本项使用 Scientific upgrade scoped checks 的 `boltz-msa` 检查：仅核对输入、共享资产/任务直接使用者、
前端材料切换与 Boltz 2.2.1 官方解析器，不下载权重或运行结构推理。

当前 Boltz 托管配方使用其官方原生 PyTorch 算子路径，适配器显式传入 `--no_kernels`；
环境没有声明安装可选的 cuEquivariance 加速库，不能依赖上游 CLI 的加速默认值。
权重、MSA、严格检查点加载和结构采样方法保持原生程序的定义；性能与加速算子版本应分开验收。
`boltz-runtime` 专项只检查官方 CLI 实际解析、两个原生三角算子与序列比对文件下载；
模型权重和真实结构预测仍通过目标环境上的前端任务验证。

## 发布编号

Windows 启动器会向指定的 X-DDE WSL 进程传递当前 HTTP(S) 代理，并保持
`localhost` / `127.0.0.1` / `::1` 直接访问。在应用 `bin/workbench.json` 中
可用可选的 `network_proxy` 保存不含认证信息的 HTTP(S) 代理地址；不修改共享
WSL 或其他应用的网络设置。升级保留同一发行版和账号的既有研究主目录与
应用代理。GitHub 文件仍通过原 HTTPS 地址下载并校验固定 SHA-256。

`pyproject.toml` 是版本权威。每次向 main 推送可发布更新，版本末位递增一次；同一候选批次的修正保留该版本。

```bash
uv run --locked python scripts/release-version.py bump
uv run --locked python scripts/release-version.py check --base PREVIOUS_MAIN_SHA
```

末位范围为 0–100，中间位范围为 0–10：`0.1.99 → 0.1.100 → 0.2.0`，`0.10.100 → 1.0.0`。编号是发布计数，独立于科学验收和数据契约。

审核改动与专项 CI 后，使用现有 **Release installers** 工作流，在已审核 main 上指定匹配的数字标签。流程构建前端和 wheel，验证版本、不可变校验和与 Windows 入口，再发布安装文件；不自动递归运行全部科研模块。

更新前检查工作台拥有的活动任务，备份状态与原始资产。安装精确提交对应的发行包，验证页面资源与发布包一致，并检查历史数据和独立科学环境保持完整。不要重启共享 WSL 或停止其他应用来完成界面升级。

OpenDDE 原生任务默认限制为 2 个 CPU、4096 MiB 内存、256 个进程，禁止使用交换空间；
独立服务器可通过 `WB_OPENDDE_CPUS`、`WB_OPENDDE_MEMORY_MIB`、`WB_OPENDDE_PIDS`
调整实际需要的预算。预算属于主机执行配置，不改写历史科研请求。Docker 必须确认内存、交换、
CPU 和进程控制器可用；创建后、启动原生程序前，还要核对容器身份和实际 HostConfig。
核对失败不会启动科研程序。实际预算证据保存在任务的 `resource-limits.json`，
原生输出和来源仍保留。超过预算可能导致任务失败，不能把该限制解释成任意大模型都能在本机运行。
资源检查与实际 cgroup/OOM 验收使用 CI 的轻量容器，不在所有者机器上运行压力测试。

所有者本机的固定入口是 `http://127.0.0.1:4322/`。每次发布后，将该入口更新到已通过专项检查的最新 `main` 发行包，再在同一地址确认版本、页面资源与受影响的交互；临时验证端口不能作为交付地址。工作空间保存成功启动的端口，后续未指定端口的启动沿用该地址。首次指定 `xdde start --port 4322`，以后的 `xdde start` 会读取同一工作空间的 `service-port.json`；无效保存值须修正，不能静默换端口。

升级时，对仍在运行的任务先核对原生执行状态。只有任务身份、科学程序标签、只读适配器和输出目录都与工作空间一致，且原生容器确实暂停时，新 Worker 才将任务保留为 `paused`。它保留输入、开始时间与已有输出，不重新派发、恢复计算或标成成功。暂停任务的取消须先确认原生停止。原生容器已经不存在的情况须单独记录为中断并保留检查点，不能声称计算仍可继续。

README 中的实际截图来自同一已审核提交的真实浏览器证据。更新截图时保留其公开案例、原生数据与截图版本，不能把生成的设计图片标成运行页面。

STAT6 的计算输入整理仅使用带复核记录、通过不可变校验的原生任务。实验构建体须在标准序列中唯一匹配；
相应 A3M 仅选择相同列与前置插入，保留原行次序，只去除区间内全缺口的行。派生文件另存并保留完整 MSA
父版本、来源任务和范围；不得把裁剪文件伪称为搜索服务的原始输出，也不放宽现有案例输入血缘验证。
预测模板可选用这组已整理材料。没有已复核的上游任务时，不自动生成替代证据。

谱系与候选比较模板可使用实际 ESM 评分中的标准序列和单点假设。保留完整原始 PLL，
仅以其负数作为越小越好的损失；两个比较队列明确共享同一标准序列对照。它们是序列模型假设比较，
不是多代优化、折叠验证、亲和力、耐药性或实验药效结果。输入整理不提交任何新的科研计算。

靶标 MSA 的结果复制沿用已配置的共享目录与远端目录，不扩大文件访问范围。只接收请求序列哈希、
靶标和链标识对应的两份 A3M；拒绝其他路径、符号链接、错误查询或深度变化，保留文件原字节与校验和。
服务返回的“不可用”错误文本不能包装为成功的同源检索结果。

候选谱系图读取分析器实际返回的改善及下降分支，保留未评分状态，不从分数推断生物进化。
DEL 留出集验证从带校验和的完整 CSV 读取全部点（最多100,000行、8MiB），不重新计算或改写模型指标。
更大或缺少完整表的历史结果必须显示实际预览数量；读取错误不得静默退回部分数据。

折叠专家输入保留原生的字符串链和含 `sequence`、`unpairedMsaPath` / `pairedMsaPath` 的链对象。
两种格式都可通过材料与步骤校验；带附加字段的对象仍须使用专家模式，不能转为简易模式时丢失 MSA。
比对文件沿既有 `asset:` 引用、实际文件摘要与共享文件发布链路传递，不允许浏览器填写主机路径。
确认页逐链列出实际氨基酸数量、候选与 MSA 使用方式，以及显式设置的采样参数；关闭 MSA 时明确说明所选文件不会参与计算。
真实比对支持输入不等于折叠或结合预测已经通过科学验收。

折叠候选的界面检查读取原生候选的布尔/数值质量标记，独立于任务完成状态与 ipTM 等置信度。
缺少、无效或相互矛盾的标记须保持未知。只有请求中所有结合端链均有有效的零起点 CDR 位置，
且原生结果明确采用相同位置语义、有实际界面接触时，才解释 CDR / 框架接触比例。
没有这些注释不能把原生默认的 0 / 1 当作真实测量；没有靶点热点时，表位检查是未评估。
界面不重算原生检查，也不改写历史结果；重新编号后的独立复核和实验参考结构比较须分别留存。
`fold-assessment-checks.yml` 只运行该解释模型、双语面板、候选选择及 Harness 路由的直接专项检查。

独立二元姿势的配体侧口袋必须通过完整的化学原子对应放到初始化构象的坐标系；蛋白侧仍使用原始结合姿势。
对完整分子做任意刚体平移不能改变二元输入的相对约束。共享复合物及分子胶保留各自的原生初始化协议。
PROTAC / RIPTAC 可在专家设置中选择固定伙伴；原生模型内部交换两端后，输出仍恢复到原始伙伴 A 的坐标系，
链 A / B 和所有来源身份不交换。模型第二伙伴的排序代理只在相同固定端方案内比较。
新执行记录保存初始化协议和固定端。历史任务缺省的新字段不进入序列化，不改变原请求摘要、原始结果或已固定数据包。
三元专项 CI 包含官方 MZ1 的独立分子坐标平移控制与实际模型执行；这些检查不证明任意新配体的预测准确性。
