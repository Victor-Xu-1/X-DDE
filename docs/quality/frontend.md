# 前端交互与视觉质量

[质量规范入口](README.md) · [长期覆盖清单](frontend-coverage.md) · [既有布局契约](../frontend-layout.md)

## 1. 目标与范围

所有页面、研究模块和交互都应有清楚的层级、可靠操作、真实反馈和一致的表现。优先保证科学/任务事实与材料身份，其次是流程、可访问性、视觉和有目的的动效。高水准设计是持续目标，不能通过自评分、动画数量或静态截图宣称已经达到某奖项水准。

延续现有冷白画布、蓝紫操作色、青绿科学强调、浅/深色 tokens、原始品牌资产、平面分区和一步一问。表格与选中分子/序列/结构并置，科学内容决定布局。先复用共享组件；不另建主题、任务状态权威或执行路径。分子显示严格遵守 [AGENTS.md](../../AGENTS.md)，本规范不复制一份可能漂移的科学参数表。

模块化按真实职责、接口契约、状态与数据所有权划界，例如预览、任务管理、编辑可以作为审查视角，不预设必须拆成三个系统。只有已证实的重复和耦合才抽取共享服务；跨模块交接保留材料/任务/版本身份，复用已有注册表和权威。重构以性能、稳定性或操作体验证据说明收益，采用小范围、可回退 PR；不为模块化重写全局架构或新增平行注册表。

[长期覆盖清单](frontend-coverage.md)用于逐步查漏。每个 PR 只验收受影响页面、共享组件的直接消费者和主要失败路径；不因「全部页面」目标就自动运行全站或科学套件。浏览器不可用时写明待验收，不能把交互候选计为有效 PR。

## 2. 操作、执行与恢复

- **一次意图一次操作。** 快速重复点击和超时重试复用现有幂等契约；提交受理后仍可找到正确任务。切任务、文件、方法或页面后，旧上传/读取/取消/重试回复不能覆盖新选择或抢回导航。真实卸载与重复打开也要覆盖。
- **事实驱动状态。** 区分提交中、服务端已受理/排队、运行、取消请求、已取消、失败与查询未知，仅用后端实际支持状态。无可信分母不显示百分比或 ETA；受理不等于完成，取消请求不等于停止，任务成功与产物加载失败分别表达。
- **恢复不丢上下文。** 慢响应、断网、刷新、深链接失败和返回操作保留正确输入/任务意图，先核对服务端再恢复。给可执行的重读/重试/返回入口，不无限 loading，不自动新建科研任务。按产品契约处理草稿与未保存修改。
- **材料与结果对应。** 选择、表格、图、原生分数/单位、下载和下一步复用对应精确输入/输出版本、记录及构象。缺值、零候选、部分失败、模板与归档计算分开说明；2D 编辑不假定保留结合姿势。
- **可理解的反馈。** 控件显示忙碌/禁用及必要原因，局部失败不吞掉独立成功数据；重要错误可读且可恢复。界面遵守现有研究者信息边界，详细关联诊断留在服务端。

## 3. 视觉与可访问性

标题、操作、标签、帮助和错误有稳定层级；保持布局宽度、间距、字级与控件对齐。长中英文、极端数值、空数据和代表性大列表不遮挡主要操作。表/图/复杂结构可在自身容器内合理滚动，不能让整页意外横向溢出。颜色和装饰不暗示不存在的科学意义。

按适用的 [WCAG 2.2 AA 要求](https://www.w3.org/TR/WCAG22/)检查键盘操作、可见且不被遮挡的焦点、合理顺序、名称/角色、文本与控件对比、非颜色反馈、错误和状态可感知。对话框关闭回到合理焦点；提示和核心选择不能只靠悬停/拖动。第三方编辑器、viewer、图表及 iframe 要实际检查键盘进出；局部通过不等于全站合规认证。

选择改动相关的桌面与窄视口，记录尺寸；沿用已有 1440/390 CSS px 基线，需要时增加宽屏、断点、文本缩放、浅深主题或中英文组合。不要为纯文案 PR 强制跑所有组合，也不以缩放截图代替响应式验收。

## 4. 动效：解释变化，不干扰研究

每段新动效说明目的、触发、终态、取消方式和静态等价：

| 场景 | 合理反馈 | 必须保持 |
| --- | --- | --- |
| 按钮、选择、上传 | 即时按下/忙碌反馈、真实阶段或一次成功强调 | 不等待动画才响应；选文件不等于上传/科学校验成功 |
| 问卷、页签、导航、局部面板 | 短过渡说明当前位置及同一对象连续性 | 输入、焦点、滚动和对象身份按原契约保持 |
| 表格、图、序列和候选切换 | 强调精确选中实体 | 不重放整表入场、不把缺数据补成平滑数值 |
| 2D/3D 与真实轨迹 | 可打断的视图变化；用户控制播放/暂停/逐帧 | 原始坐标/键阶/时间刻度不变；不同模型不伪装成物理运动 |
| 提示、对话框、状态更新 | 短入场或直接显示，一次真实状态提示 | 焦点不依赖动画结束；轮询不重复播报/闪烁 |

优先沿用 [useReveal](../../frontend/src/presentation/useReveal.ts) 的局部 180 ms/7 px 和[选中标记](../../frontend/src/presentation/active-indicator.css)的 220 ms 节奏，按实际目的调整并记录理由；这些是已有实现基线，不是官方奖项指标或普适性能保证。新动效优先采用不触发布局的 transform/opacity，实际成本仍需测量。[CSS 动画性能指南](https://web.dev/articles/animations-guide)

在真实状态变化时触发；不要随轮询、每次 render 或旧回复重新播放。可中断、可清理，不复制整张表或 WebGL 画布来制造过渡，不无故引入大型依赖。静止研究视图不自动持续旋转或装饰渲染；离开/隐藏后停止非必要动画，不误停服务器任务。动效不能触发安装、上传、计算或改变科学源文件。

默认遵从系统 `prefers-reduced-motion`，新动效关闭非必要位移、缩放与循环，保留相同状态和操作；检查运行时偏好变化以及 CSS/脚本/第三方视图。可关闭非必要交互动效是项目主动要求，不混称 WCAG AA 的通用动效条款。自动移动/更新内容按适用要求提供暂停、停止、隐藏或频率控制；禁止用闪烁吸引注意。[WCAG 动效与时间要求](https://www.w3.org/TR/WCAG22/#enough-time)

## 5. 按问题测性能

性能优化先约定可验证目标，再用同设备、浏览器、输入规模、操作序列和冷/热条件对照，记录重复次数及分布。按问题选请求/重复提交数、响应/渲染耗时、长任务、帧间隔、首包增量、内存/监听器/WebGL context 趋势，勿为小样式修改测全套。

- 切换/重复点击不增加科学提交，动效不提高轮询频率；大表/长序列保持有界分页或渲染。
- 反复进出检查动画、请求、监听器与 viewer 生命周期，区分正常缓存与持续泄漏趋势。
- 普通交互不等动画结束，静置无新增非必要循环；复杂科学 viewer 单列就绪/绘制成本。
- 团队在实际基线后确定场景预算；没有数据不宣称「更快」「无泄漏」或所有设备固定帧率。不能靠降科学精度、隐藏失败或缩小真实数据冒充优化。

如使用 LCP/INP/CLS，区分实验室样本与真实用户第 75 百分位指标；一次本地测量不是全站 Core Web Vitals 通过。[Web Vitals](https://web.dev/articles/vitals)

## 6. 轻量真实浏览器验收

实际可见变化检查候选真实页面；交互变化走通受影响流程及主要失败/恢复路径。截图标注 SHA/构建、页面/状态、浏览器/视口及数据来源；有视觉变化时尽可能同条件前后对照，无法取得基线时说明限制。动效或异步问题用实际操作及必要的短录像/trace，截图一帧不能证明其正确性。

一名非作者独立查看实际画面和相关操作证据，解决阻塞即可；同一有效 SHA/树证据可复用，不要求多轮重复全量 review。代码、DOM 断言、生成设计图和旧截图不替代当前浏览器验收。明确标注夹具/模拟接口，其结果不冒充原生科学运行。

每个 PR 从[七项清单](evidence.md)选择适用项，补一段前端证据即可。全部适用 CI 与本次必要的浏览器检查通过才称该范围已验收；无新增阻塞不等于整个产品视觉评估完成。
